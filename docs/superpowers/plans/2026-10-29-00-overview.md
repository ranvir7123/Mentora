# Project X build: overview and parallel streams

> **For agentic workers:** this file is the map. Each stream has its own plan (files 01–06 in this folder).
> REQUIRED SUB-SKILL for a stream session: superpowers:executing-plans (or subagent-driven-development) on
> that stream's plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the design in `docs/superpowers/specs/2026-10-29-tutorial-to-practice-design.md` by
Mon 2 Nov night (feature freeze), with four AI coding sessions working at once after a short shared start.

**Architecture:** One Python 3.12 program. A small shared core (`app/core/`) defines what every part
agrees on: the app plug-in interface, check and operation menus, the lesson file, the lesson runner and
the screen-facing backend. Each stream then builds against that core alone: the screens against a fake
backend, the Excel and VS Code plug-ins against the plug-in interface, the lesson factory against a fake
plug-in and saved Meta answers. The integration session joins them.

**Tech stack:** Python 3.12, PySide6 (full: Qt Quick + Qt Multimedia), pywin32, comtypes, openai client
(Meta's API), yt-dlp, ffmpeg, pytest; a TypeScript VS Code extension (Node 24).

**Spec:** `docs/superpowers/specs/2026-10-29-tutorial-to-practice-design.md`

## Global Constraints

Every task in every stream plan includes these.

- Python: `C:\dev\meta-hackathon\.venv\Scripts\python.exe` (also from worktrees; `pytest.ini` puts the
  worktree root on the import path). Tests: `<python> -m pytest -q`. Tests take seconds and need no Excel,
  no VS Code, no network and no key: live work lives in `probes/` and is run on purpose.
- Live runs (real Excel, real VS Code, screenshots at 200%, the tester) happen one at a time on Ranvir's
  laptop. Before one: check free memory and tell Ranvir which sessions to close. The tester moves the real
  mouse: it runs only after Ranvir says he's away.
- Meta models only (Muse Spark series, Muse Wonder, Muse Image, Muse Voice Transcribe, SAM 3.1,
  Glimmer / Spark Open, Muse Code agent); never a "-contributor" version. API `https://api.meta.ai/v1`
  through `app.meta.client`. The key comes only from `app.meta.key.require_key()`; never print, log or
  commit it. Git hooks stay on: `git config core.hooksPath tools/hooks`.
- Old Project X (`C:\dev\ProjectX`) is a reference. A lifted helper gets its own commit starting
  "Adapted from Project X : <what> (<old path>). Changed: <what changed>" and a README row. Never copy its
  screens, its lessons, or any file that calls a non-Meta model.
- Never commit a video or download: they live in `recordings/` (git ignores it).
- Dark mode only. Never build, check or mention a light mode.
- Words on screen: plain, second person, sentence case; instructions at most 12 words; never "simply" or
  "just"; no "tutor", "AI teacher" or "chat" in any name or first sentence.
- The AI never ticks a step: only check functions over snapshots do.
- Every Excel lesson's sheet fits in the columns visible at 920 px wide.
- Commit small and often. No attribution or co-author lines.
- Excel COM calls run only on the Excel COM thread; event handlers never call Excel.

## Review Focus (whole project)

The input classes most likely to bite a learner that no single happy-path test covers. Each line names the
plan whose tests pin it.

1. The learner is still typing in a cell when a read is due → Excel never freezes and the read happens
   once they leave the cell (03, Task 3 test `test_busy_read_is_retried_until_the_cell_is_left`).
2. The learner does a step a different right way (`=B2+B3+B4+B5+B6` instead of `=SUM(B2:B6)`, or types the
   number instead of a formula) → right ways tick, wrong ways get "Not yet" naming the difference (03,
   Task 4 tests: three right ways and three wrong ways per check kind).
3. The learner closes Excel mid-lesson → the panel says Excel was closed and offers to reopen, nothing
   crashes (03 Task 2 `test_closed_workbook_is_reported`, 06 Task 4 `test_app_closed_shows_reopen_and_reopen_resumes`).
4. Excel is moved, resized, scrolled or zoomed while the ring shows → the ring follows within 2 px
   (03 Task 6 pure tests on the cell-rectangle maths; probe at 100/150/200%).
5. Muse Spark returns a broken or off-menu lesson, or refuses the video → the factory shows "not ready"
   with the reason and never crashes (04 Task 4 tests on saved bad answers).
