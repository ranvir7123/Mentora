# Shared contracts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Commit the small shared core every stream builds against: the app plug-in interface, check and
operation menus, the lesson file, the lesson runner, the screen contract and the hand-written budget lesson.

**Architecture:** `app/core/` is pure Python with no Qt, no Excel and no network. Plug-ins, screens and the
lesson factory depend on it; it depends on nothing of theirs. A fake plug-in (a dictionary pretending to be
an app) lets every other stream test without real software.

**Tech Stack:** Python 3.12 standard library (dataclasses, typing, concurrent.futures, json), pytest.

**Spec:** `docs/superpowers/specs/2026-10-29-tutorial-to-practice-design.md` (sections 2.2, 5.2, 5.3)

## Global Constraints

See `2026-10-29-00-overview.md`, "Global Constraints". In short: `<py>` below means
`C:\dev\meta-hackathon\.venv\Scripts\python.exe`; tests need no Excel, network or key; plain words on screen,
instructions at most 12 words, never "simply" or "just"; the AI never ticks a step; no attribution lines.

## Review Focus

1. A learner does two steps in one go (types the total and formats it before the panel catches up) → both
   tick in order on one snapshot (Task 6 `test_doing_two_steps_at_once_ticks_both`).
2. A learner repeats the same wrong answer while Excel re-reads every second → "Not yet" shows once, not
   every second (Task 6 `test_wrong_try_says_not_yet_once_until_it_changes`).
3. A learner undoes a finished step → "Step N changed" appears and goes when fixed; nothing goes backwards
   (Task 6 `test_undoing_a_done_step_says_it_changed_and_fixing_it_clears`).
4. A check function crashes on an odd workbook → the lesson keeps waiting instead of crashing (Task 6
   `test_a_check_that_raises_is_treated_as_waiting_and_recorded`).
5. A hand-edited or AI-written lesson file is missing a field or breaks a rule → loading names the problem
   instead of crashing later on screen (Task 5 `test_validate_names_every_problem`).

- Produces in `plugin.py` (typing `Protocol`s; every `Future` is `concurrent.futures.Future`):

```python
class AppPlugin(Protocol):
    app_id: str                                  # "excel", "vscode"
    title: str                                   # "Excel"
    checks: Mapping[str, CheckKind]
    ops: Mapping[str, OpKind]
    target_kinds: frozenset[str]
    def validate_starter(self, starter: Mapping) -> list[str]: ...
    def open(self, lesson: "Lesson", workdir: Path, *, visible: bool = True, resume: bool = False,
             on_snapshot: Callable[[Any], None], on_closed: Callable[[], None]) -> "AppSession": ...

class AppSession(Protocol):
    def hwnd(self) -> int: ...                   # 0 when invisible
    def latest(self) -> Any | None: ...          # last snapshot delivered
    def read_now(self) -> Future: ...            # -> snapshot
    def perform(self, op: Call) -> Future: ...   # -> None; the Future raises if the app refused
    def reset(self) -> Future: ...               # -> None; back to the starter state
    def locate(self, target: Target) -> Future: ...   # -> Spot | None
    def watch(self, target: Target | None, on_spot: Callable[[Spot | None], None]) -> None: ...
    def set_waiting(self, waiting: bool) -> None: ...  # the 1 s idle re-read while a step waits
    def place(self, rect: Rect) -> Future: ...   # put the app's window here (physical px)
    def close(self, save: bool = False) -> None: ...
```

`resume=True` opens the program's own saved work copy in `workdir` when there is one (else the starter);
`close(save=True)` saves that work copy so the learner can continue later. Neither ever touches a file of
the learner's own.

`on_snapshot` and `on_spot` may be called from the plug-in's own thread and must return at once.
`watch` re-locates while a target is set and calls `on_spot` only when the spot moved by 1 px or more;
`watch(None, ...)` stops.

- Produces in `fake_plugin.py`: `FakePlugin()` with `app_id="fake"`; its app state is a `dict[str, Any]`;
  a snapshot is a plain `dict` copy. Checks: `equals(key: text, value: value)` (attempted when the key is
  present), `has(key: text)`. Ops: `set(key, value)`, `delete(key)`. Target kinds: `{"key"}`.
  `FakeSession` adds test helpers `learner_sets(key, value)` (changes state and delivers a snapshot, as a
  learner would), `refuse_next(n)` (the next n `perform` calls fail), `closed_by_learner()`.
  Every Future it returns is already done. `close(save=True)` writes the state to `workdir/state.json`;
  `open(resume=True)` reads it back. `open` needs only `lesson.id` and `lesson.starter`, so these tests
  pass a `SimpleNamespace(id="t", starter={"a": 1})` until Task 5's `Lesson` exists.

### Task 6: The lesson runner

**Files:**
- Create: `app/core/runner.py`
- Test: `tests/core/test_runner.py`

**Interfaces:**
- Consumes: `Lesson`, `Step`, `Verdict`, `CheckKind`.
- Produces:

```python
@dataclass(frozen=True) class StepPassed:   index: int; first_try: bool; points: int
@dataclass(frozen=True) class NotYet:       index: int; text: str; code: str
@dataclass(frozen=True) class StepChanged:  index: int          # a done step's check now fails
@dataclass(frozen=True) class StepFixed:    index: int
@dataclass(frozen=True) class LessonDone:   seconds: float; points: int; first_try: int; steps: int
@dataclass(frozen=True) class StepRecord:   step_id: str; tries: int; hints: int; seconds: float; first_try: bool

class LessonRun:
    def __init__(self, lesson: Lesson, checks: Mapping[str, CheckKind], *,
                 clock: Callable[[], float] = time.monotonic, points_per_step: int = 10): ...
    index: int                      # current step; == len(steps) when done
    done: bool
    changed: frozenset[int]         # done steps that now fail
    errors: list[str]               # check crashes, kept for the log (at most 20)
    def on_snapshot(self, snap: Any) -> list[object]: ...
    def hint(self) -> str | None: ...           # next hint for the current step, None after the third
    def hints_shown(self) -> tuple[str, ...]: ...
    def records(self) -> list[StepRecord]: ...  # one per finished step, in order
```

Rules for `on_snapshot` (one pass, events in this order):
1. Re-check every done step: newly failing → `StepChanged`; failing step now passing → `StepFixed`.
2. While the current step's check is right: `StepPassed` (first_try = no `NotYet` shown for it), move on.
   Several steps can pass on one snapshot.
3. If the current step is attempted and wrong and its `code` differs from the last code shown for this
   step: count a try and emit `NotYet` with the matching mistake's `not_yet` line when a mistake has the
   same non-empty `code`, else the verdict's `text`. Not attempted → forget the last code shown.
4. After the last step passes → `LessonDone`.
A check that raises counts as `Verdict.waiting()` and appends its traceback's last line to `errors`.
